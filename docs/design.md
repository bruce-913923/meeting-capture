# Meeting Capture 設計

macOS 選單列小程式：線上會議（Teams）開始後按「開始」，同時錄系統聲音、截簡報、抓字幕；按「結束」後在本機轉文字，再交給 AI（Claude 或 Codex）整理成文章，依使用者選的 skill 輸出到本機或 Notion。

## 原則：app 是中介，流程由 AI 決定

| 由 app 做 | 由 AI 決定 |
|---|---|
| 找會議視窗、錄音、截圖、字幕 OCR、轉文字 | 結束後要問使用者哪些問題、推薦哪個選項 |
| 掃 skill 清單、切換 Claude 或 Codex | 文章怎麼寫、放哪裡（照使用者選的 skill） |
| 依 AI 回傳的 JSON 畫對話框、顯示進度 | 執行輸出（寫檔、上傳）並回報結果 |

安全界線：AI 的「規劃」回傳只能是少數題型（單選、多選、文字、確認），app 只負責畫出來並把答案傳回去，不執行 AI 指定的任何動作。會改外部資料的事只在「執行」那次呼叫裡由 AI 自己做，並限制可用工具。

## 流程

```
開始 → 選擇要截的視窗（預設最大的 Teams 視窗；有「彈出視窗」就選它）
     → 檢查喇叭沒有靜音（靜音錄不到聲音）
     → 同時：錄系統聲音（每 10 分鐘一段 m4a）、每 4 秒截一次視窗、OCR 字幕
結束 → 轉文字（使用者設定的引擎與模型）
     → 規劃：AI 讀會議資料夾＋選定的 skill，回傳問題 JSON
     → app 畫對話框，使用者確認
     → 執行：AI 依答案產出文章並輸出，回傳結果 JSON
     → 通知（附連結或檔案位置）
```

## 會議資料夾

`~/MeetingCapture/<日期>-<時間>-<標題>/`

- `meta.json`：標題、開始結束時間、視窗、截圖張數、引擎
- `audio/*.m4a`：每 10 分鐘一段
- `frames/*.jpg`：換頁時的整個視窗原圖（切錯時可重切）
- `slides/*.jpg`：自動切出的簡報區；切不出來或貼邊時改存整個視窗並記在 `slides/index.json`
- `captions.txt`：字幕 OCR（去重、附時間）
- `transcript.txt`：轉文字結果（附時間）
- `article.md`：預設動作產出的文章

## 截圖防切到（三層）

1. 每次換頁保留整個視窗原圖。
2. 不用固定比例：每張找「四周是純黑邊框的最大區塊」當簡報區。
3. 優先截 Teams 的「彈出視窗」（分享內容獨立成視窗時直接截它）。
   切出來的區塊若貼到邊緣、四周沒有背景色，判定可能切到，改存原圖並標記。

## 轉文字引擎（可替換）

設定裡選「引擎類型＋模型路徑」，存檔前先用一段 `say` 產生的中文測試音檔試跑：

- `mlx`：MLX Whisper 相容模型（例如 Breeze-ASR-25 MLX），Apple Silicon
- `faster-whisper`：CTranslate2 模型資料夾
- `apple`：macOS 內建語音辨識，不用模型路徑，準確度較低

Python 引擎需指定 Python 路徑（有裝對應套件的環境）。

## AI 中介

- 提供者：`claude -p`（`--json-schema`）或 `codex exec`（`--output-schema`）。不用 SDK：這個工具是一次性批次工作，不需要中途暫停或來回對話。
- skill 清單：掃 `~/.claude/skills`、`~/.codex/skills`、`~/.agents/skills` 的 `SKILL.md`，加上 app 內建的「預設會議文章」規則；可手動加路徑。
- 兩次呼叫：規劃（唯讀，回傳問題）→ 執行（依答案輸出，回傳結果）。

## 已知限制

- 用 ad-hoc 簽章，每次重建 app 都要重新授權「螢幕與系統錄音」。
- 命令列的 `claude` 要另外授權 Notion 連線（桌面 app 的連線不共用）。
- Codex 那邊沒有 Notion 連線時，選 Notion 類的 skill 會失敗。
